Netskope One · Private Access · Privileged Remote Access

PRA 特權遠端存取：取代跳板機，瀏覽器直接 RDP／SSH Privileged Remote Access: replace the jumpbox with browser RDP / SSH

管理員、外包與廠商不需要 VPN，也不用安裝 Client，用瀏覽器就能經 NPA Browser Access 連到內部的 RDP、SSH 主機。PRA 在原有存取政策之上加上連線層級的控管：整段連線是否錄影（Session Governance）。預設由使用者自行輸入主機帳密，也可以選用 Credential Injection 從保管庫自動帶入，讓使用者不必知道共用密碼。 Admins, contractors and vendors reach internal RDP and SSH hosts through NPA Browser Access from a browser, with no VPN and no Client. PRA adds session-level control on top of existing access policy: whether the session is recorded (Session Governance). By default users type the host login; optionally, Credential Injection fills it in from a vault so users never learn the shared password.

01 · Interactive Simulator

兩段政策：先決定能不能連，再決定怎麼連Two policy stages: whether to connect, then how

第一段是即時防護（RTP）政策，決定使用者能不能存取這台主機；第二段是 PRA 政策（由上而下、命中即止），決定要不要錄影，以及是否選用自動帶入帳密（預設由使用者自行輸入）。PRA 政策本身不會允許或拒絕存取。Stage one is Real-time Protection (RTP) policy, which decides whether the user may reach the host. Stage two is PRA policy (top-down, first match wins), which decides recording and optional credential injection (by default users type the login). PRA policies never grant or deny access.

02 · Test Record

實測紀錄：錄影畫面與 Skope IT 事件Test record: session recording and Skope IT event

實際以瀏覽器 RDP 連到 Win11 主機，Session Governance 政策「Recording_Win11_host4_Policy」錄下整段連線。管理員可在 Skope IT › Network Events 找到這筆事件並下載錄影；一般使用者無法查看或下載。帳號與公網 IP 已遮蔽。A browser RDP session to a Win11 host was recorded by the Session Governance policy "Recording_Win11_host4_Policy". Admins find the event under Skope IT › Network Events and download the recording; end users cannot view or download it. Account and public IP are masked.
