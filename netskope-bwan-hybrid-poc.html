02 · Technical Architecture Highlights

關鍵技術架構Key Architecture

One-Arm 部署優勢Why One-Arm

NSG 以單一介面掛在既有防火牆內側網段，像一台內網伺服器，而非串接（In-line）設備。The NSG sits on the inside segment of the existing firewall with a single interface, like an internal server rather than an in-line appliance.

  • 不改拓撲：既有預設路由、防火牆、上網政策全部維持，NSG 預設閘道指回防火牆。No topology change: existing default routes, firewall and internet policies stay as-is; the NSG's default gateway points back to the firewall.
  • 不需 PBR：引流決策由端點 Client 完成，Microsoft / GenAI 流量以 overlay 目的位址直接送到 NSG，交換器與防火牆不需依應用做策略路由。No PBR: the steering decision is made on the endpoint; Microsoft / GenAI traffic is sent to the NSG as the overlay destination, so switches and firewalls need no app-based policy routing.
  • 影響面最小：NSG 異常只影響被導流的 Microsoft / GenAI 流量，中國境內網站照常由 China Premium POP 出口。Small blast radius: an NSG issue only affects steered Microsoft / GenAI traffic; China domestic sites keep egressing via the China Premium POP.
  • 防火牆只需放行 IPsec：對外只多 UDP 500 / 4500（NAT-T），ESP 封裝於 UDP 中可穿越 SNAT。Firewall only allows IPsec: just outbound UDP 500 / 4500 (NAT-T); ESP is UDP-encapsulated so it traverses SNAT.

API 自動建 IPsec（CSS）API Auto-Provisioned IPsec (CSS)

BWAN Orchestrator 以 Netskope REST API v2 Token 串接租戶，自動完成 IPsec Site 生命週期管理。The BWAN Orchestrator connects to the tenant with a Netskope REST API v2 token and manages the IPsec site lifecycle automatically.

  1. 1Cloud Account 驗證：Orchestrator 以 Tenant URL + API v2 Token 連線 Netskope Console。Cloud Account auth: the Orchestrator connects to the Netskope Console with the tenant URL + API v2 token.
  2. 2查詢 POP：取得可用 NewEdge POP 與 IPsec Gateway 位址，選定 TPE1 / SIN1。Discover POPs: fetch available NewEdge POPs and IPsec gateway addresses; select TPE1 / SIN1.
  3. 3註冊 IPsec Site：以防火牆 SNAT 後公網 IP 為 Source Peer，自動產生 PSK。Register IPsec site: use the firewall's post-SNAT public IP as the source peer and auto-generate the PSK.
  4. 4派發至 NSG：PSK、Peer、Primary / Secondary POP 下發給 NSG，啟動 IKEv2。Push to NSG: PSK, peers and primary / secondary POPs are pushed to the NSG, which brings up IKEv2.
  5. 5持續監控：Tunnel 狀態雙向可見，Console 端 IPsec 頁面顯示 Up。Monitor: tunnel state is visible on both sides; the Console IPsec page shows Up.

雙層高可用（HA & Fallback）Two-Layer HA & Fallback

隧道層與閘道層各自具備故障處理，確保 Microsoft / GenAI 流量受控且使用者不斷網。Tunnel and gateway layers each handle failures, so Microsoft / GenAI traffic stays governed and users stay online.

Tunnel-level

Primary TPE1 IPsec 經 DPD / 健康檢查判定異常時，NSG 於數秒內切換至 Secondary SIN1，SkopeIT Pop Name 隨之變為 SIN1，政策維持一致。When DPD / health checks mark the primary TPE1 tunnel down, the NSG fails over to secondary SIN1 within seconds. The SkopeIT Pop Name changes to SIN1 and policies stay the same.

Gateway-level

NSG 離線或不可達時，端點 Client 自動 Fallback，改由 SWG Client Tunnel 連往 GSLB 選出的就近 POP，使用者不斷網，流量仍受 Netskope 政策保護。If the NSG is offline or unreachable, the Client falls back to the SWG Client Tunnel toward the nearest POP chosen by GSLB. Users stay online and traffic is still protected by Netskope policy.

分點位於中國時，Fallback 後 Microsoft / GenAI 流量的出口與可達性需特別確認；若合規要求必須經 TPE1 / SIN1 出口，可評估 Fail-close，並於 PoC 中分別驗證兩種模式。For branches in China, verify where Microsoft / GenAI traffic egresses after fallback and whether it stays reachable. If compliance requires TPE1 / SIN1 egress, consider fail-close and test both modes in the PoC.
