Hub Groups：上千個 Client 怎麼分散、怎麼備援、IP 從哪裡來 Hub Groups: how thousands of Clients spread out, fail over, and get their IP

Hub Group 把同一地點或不同地點的 Hub 邏輯上綁成一組。Client 從組內隨機、或依地理位置挑出 Primary 與 Secondary，跟 Primary 建 Tunnel 並從它的 IP Pool 拿到虛擬 IP；Primary 故障時自動切到 Secondary，並換成 Secondary Pool 的 IP。每台 Hub 的 Pool 必須唯一，用 BGP 自動宣告彙總路由。 A Hub Group logically bundles Hubs at one or several locations. The Client picks a Primary and Secondary from the group, at random or by geolocation, tunnels to the Primary and gets a virtual IP from its pool; if the Primary fails it moves to the Secondary and gets a new IP from that pool. Each Hub's pool must be unique, and BGP advertises the summary automatically.

02 · Sizing

Hub 數量與 IP Pool 計算Hub count and IP pool sizing

依文件公式：Pool 要能吸收其他 Hub 故障時轉過來的使用者，所以建議 Pool 以「最少 Hub 數」來除，而不是以實際部署的台數來除。Per the document: a pool must absorb users failing over from other Hubs, so the recommended pool divides by the minimum Hub count, not by the number of Hubs deployed.
