即時防護政策：順序決定結果 Real-time Protection: Order Decides the Outcome

即時防護政策由上而下逐條比對，命中就執行該動作並停止往下比對；只有設為 Alert 與 Continue 的 DLP 政策例外。都沒有命中時，Netskope 預設允許。所以政策要由精確到廣泛排列：Threat → Utility → RBI → CASB → Web → NPA。 Real-time Protection policies are evaluated top-down. The first match applies its action and evaluation stops; only DLP policies set to Alert and Continue keep going. If nothing matches, Netskope allows by default. So order policies from specific to broad: Threat → Utility → RBI → CASB → Web → NPA.

動態 URL 分類（Dynamic URL Classification）Dynamic URL Classification

URL 不在 Inline（NSProxy）資料庫時，系統會非同步查詢另一個更大的資料庫找出正確類別。結果在同一個 POP 的所有執行個體間共享 12 小時，到期後再次存取時自動更新。When a URL is not in the inline (NSProxy) database, the system starts an asynchronous lookup in a second, larger database. The category is shared across all instances in the same POP for 12 hours and refreshed automatically on the next access after it expires.
