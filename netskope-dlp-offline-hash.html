機敏資料不出門：地端產生雜湊，只把雜湊送上雲 Sensitive data stays home: hash on-prem, send only hashes

地端 Ubuntu 主機以唯讀方式掛載 File Server，在本機為客戶資料 CSV（EDM）或機敏文件與圖片（Fingerprint 2.0）產生雜湊，再透過 REST API 只把雜湊上傳到 Netskope。cron 排程每天自動同步，DLP 比對資料庫隨時保持最新，原始檔案從不離開企業。 An on-prem Ubuntu server mounts the file server read-only, hashes customer-data CSVs (EDM) or sensitive documents and images (Fingerprint 2.0) locally, and uploads only the hashes to Netskope via REST API. cron keeps the DLP match data current every day, and the original files never leave the organization.

03 · Scheduling & Operations

排程、前置需求與疑難排解Scheduling, prerequisites and troubleshooting

兩個排程錯開 30 分鐘，並以 flock 避免重疊執行Two jobs staggered by 30 minutes, with flock to prevent overlapping runs

兩個工作在同一台主機上執行，錯開時間可避免 CPU、記憶體與網路互搶；flock -n 讓同一個工作若上一輪還沒跑完，這一輪就直接略過。Both jobs run on the same server; staggering avoids CPU, memory and network contention. flock -n skips a run if the previous run of the same job is still going.

# crontab -e
PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin
# 1. Netskope FP2 Sync (Daily at 18:37 with execution lock)
37 18 * * * flock -n /tmp/fp2.lock /root/netskope-fp2/fp2_auto.sh >> /var/log/netskope_fp2.log 2>&1
# 2. Netskope EDM Sync (Daily at 19:07, 30-minute offset, with execution lock)
07 19 * * * flock -n /tmp/edm.lock /root/netskope-edm/edm_auto_processed.sh >> /var/log/netskope_edm.log 2>&1
