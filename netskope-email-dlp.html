Netskope One · Email DLP · SMTP Proxy

現代化 Email DLP：外寄郵件的統一資料防護 Modern Email DLP: Unified Protection for Outbound Mail

只要在 Microsoft 365 或 Gmail（Google Workspace）設定外寄 Connector，外寄郵件就會先經過 NewEdge 上的 Netskope SMTP Proxy，檢查後交給外寄閘道（Proofpoint／Mimecast）派送。郵件內文與多層附件由同一套 DLP 引擎檢查，再依收件網域插入 X-DLP-Action Header 或剔除收件者；實際的阻擋與主管簽核由 Exchange（或 Gmail）依 Header 執行，並在 Outlook 通知寄件者。使用者不需安裝任何外掛。 Configure an outbound connector in Microsoft 365 or Gmail (Google Workspace) and outbound mail passes through the Netskope SMTP Proxy on NewEdge, then goes to the outbound gateway (Proofpoint / Mimecast) for delivery. Body text and nested attachments are checked by the same DLP engine, then, by recipient domain, Netskope adds an X-DLP-Action header or removes recipients; Exchange (or Gmail) enforces the block or manager approval from the header and notifies the sender in Outlook. Users install nothing.

03 · Remediation

Netskope 標記、郵件平台執行：四種處置Netskope marks, the mail platform enforces: four actions

X-DLP-Action: Block

Header 阻擋Block via header

Netskope 不直接攔信，而是插入 Block Header，由 Exchange 傳輸規則依 Header 擋下郵件。Netskope does not drop the mail; it adds a Block header and an Exchange transport rule stops the email.

X-DLP-Action: RequireApproval

Header 主管簽核Manager approval via header

插入 RequireApproval Header，Exchange 傳輸規則自動把郵件送給寄件者主管簽核，核准後才寄出。Adds a RequireApproval header; an Exchange transport rule automatically sends the mail to the sender's manager and releases it only once approved.

REMOVE RECIPIENT

剔除收件者Remove recipient

精準移除非法外部收件人，合規通訊不中斷。Removes only unauthorized external recipients; compliant communication continues.

OUTLOOK NOTIFICATION

Outlook 即時通知Outlook notice

郵件被阻擋或送審時，寄件者在 Outlook 收到通知，說明違反的原則，養成資安意識。When mail is blocked or held, the sender gets a notice in Outlook explaining the policy, building awareness.
